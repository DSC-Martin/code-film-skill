# 敘事片／手繪風／角色動畫

> 產品片是「功能清單的舞台劇」；敘事片是「一個有起承轉合的小故事」——例如「small print」：
> Claude 每天收到一堆請求，圈出其中「人的那一部分」丟進罐子，夜裡那些字變成星星、連成星座。
> 來源與證據等級見 research.md。

## 一、先定節拍，再定畫面

1. **一句話故事**：主角是誰／想要什麼／什麼改變了。說不出來就還不能動工。
2. **節拍格**：定 BPM（慢 72–90、中 100–120）與段落 intro → build → peak → ending。
   timeline.json 加 `"bpm": 120`，所有剪接點用 `beatFrame(n, bpm)` 算——verify 會檢查剪接是否在拍上。
3. **鏡頭表**（STORYBOARD-story.md）：10–20 鏡，**全部在同一個連續世界**；每鏡寫：
   拍號區間／鏡位（世界座標 x,y、zoom）／畫面／動作／聲音。換鏡＝`Camera` 在世界中移動，
   不是換背景。需要真正換場（時間跳躍、夢境）才用 SceneShell 淡出淡入。
4. **事件表**：動作與音效共用同一份（timeline.json `sounds`）。

## 二、手繪感

- 所有抖動、筆觸、紋理都用**固定種子**：`rng(seed)`，禁 `Math.random()`（每格必須是時間的純函數）
- `InkPath`：折線細分＋抖動＋雙筆觸＝墨線；`progress` 逐筆畫出；`boil={4}` 每 4 格換種子＝線條沸騰
  （傳統手繪動畫的 12fps 微抖，讓靜止畫面也活著）
- 填色晚於線條出現（先勾線再上色，像真的在畫）
- 紙紋：一層低不透明度的固定種子雜點（整片共用同一張，不要每格重算）
- 文字一律用字型「打」出來（TypeOn／Caption），不要用路徑畫字——拼字永遠正確

## 三、角色

- 角色＝多個 SVG 零件（頭、身、手、腳各一個 `<g>`）；**只動 transform**（translate／rotate／scale），不動版面
- 每個零件的**樞紐點**設在關節（`transform-origin` 或 `rotate(a cx cy)`），否則轉動時零件會飄
- 表演節奏：預備動作（往反方向一點）→ 主動作 → 過衝 → 回穩（spring 的 damping 10–14 就有過衝）
- 次要動作延後 3–6 格（頭先轉、身體跟、頭髮最後）
- 用 GSAP 等時間軸庫時：**暫停時間軸、由目前格數驅動**，不可讓它自己跑 requestAnimationFrame
- 避開第一版常見毛病：粗圓外框（看起來幼稚）→ 用細墨線＋不均勻線寬；表情靠眼睛與眉毛的位移，不要靠誇張的嘴

## 四、聲音

- 和弦底配合段落（build 加一層、peak 最滿、ending 抽掉）
- 每個重要動作一個合成音效，**音量不要有突兀的單擊**（verify 突兀音量閘）
- 片尾給一個解決和弦（C–E–G–C'）

## 五、敘事片驗收（verify.py 全部適用，另加）

- `bpm` 存在 → 自動檢查剪接在拍上
- 抽格總覽：每 0.5 秒一格（`contact_sheet.py` 給一串格號），看節奏與「有沒有長段不動」
- 自問三題（人看，機器量不到）：一句話故事有沒有講完？主角有沒有改變？結尾有沒有情緒落點？
- 模型預設會走向最安全、最平均的版本——**第一版一定要有人否決平庸處**，再修第二版
